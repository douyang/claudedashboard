Posting from another Claude session

Every Claude session that works on a project reports here through this artifact's database. The claude-dashboard skill holds the full procedure. Reuse a document id to update a record in place.

Who reads what. The board owner's collections below are readable and writable by the board owner only. Every other person writes to their own private subtree, data/users/me/profile/ followed by the collection name (projects, sessions, jobs, ticks, syncs). The board resolves me to the writer. Only that person and the board owner read the subtree. The document data/users/me/profile holds the person's limit state in the field quota, with the same fields as meta/quota. A person who opens the board lists themselves in join/<their id> (name, joinedAt, seenAt; the board owner adds label). The collections that follow have the same fields in every subtree.

Project names. The board names a project after its repository: the first owner/repo of the project, in the registry or in its sessions. A project without a repository takes the name of its folder, for example a Cowork project. A project with neither keeps its own name. Two registry documents with the same repository are one project. A session that touched several repositories belongs to its first repository, unless a registry document lists the session in sessions. A name that a project had before stays valid as an alias: job rows that use it keep their project.

projects/<slug>: one document per project. Fields: name (the rule above), aliases (other names that job rows use), where (cloud or local; derived when absent), surface, sessions (session ids), repos (the first one names the project), folder (names a project that has no repository), artifacts, status (active, paused or done), pinned, note, color (a fixed colour slot, 1 to 8; without one the project draws in grey as Other), lastActivityAt (set on each report; it keeps the project active for 72 h).

sessions/<session id>: one document per session, rewritten as it runs. Fields: title, project, repos, folder, where, surface, status, createdAt, updatedAt, tok (input, cache reads, cache writes and output together), out, usd, src, and partial when the figure is a floor. When the Claude Code Remote connector answers, the board reads cloud sessions live and those figures replace the stored ones.

syncs/<epoch seconds>: one document per hourly sync, written by a scheduled routine from list_sessions. Fields: at, sessions (id, title, status, bucket, model, createdAt, updatedAt, tok, out, usd, repos), quota. The newest sync of each person supplies that person's cloud sessions. It keeps cloud figures current when the page cannot read Claude Code Remote itself.

ticks/<session id>~<UTC day>: usage snapshots from a session or from this page, pts as [epoch seconds, tokens]. Fields: sid, project, at, tok, out, usd, src. Velocity and the chart come from these snapshots. This page also writes one when it reads a changed live total.

jobs: project, group
The project and a sub-heading inside it.
label, note
What the job is, in one line, and the latest detail.
surface
Where it runs: Claude Code · web (cloud), Claude Code · CLI or Cowork (local).
status
queued, running, waiting (needs a person), done, failed or stopped.
blocked
What the job waits on.
total, done, unit
Progress, for example 4320 of frames.
rate, estSec
Units per second, and the expected length in seconds.
order, due, link
Sort key, a deadline as 2026-10-15, and an https address.
askedAt, answeredAt, answer
A question to a person, when they answered, and what they decided.
queuedAt
When the job joined the queue.
tok, tokOut, tokEst
Tokens used so far, the output tokens among them, and the expected total.
startedAt, updatedAt, finishedAt
Timestamps in UTC, as 2026-10-01T06:21:41Z. A running job with no report for 30 minutes is stale.

meta/board holds a note and updatedAt. meta/quota holds the board owner's account limit as Claude Code reports it (other people store it in the field quota of their profile document): status (allowed, allowed_warning or rejected), type (for example five_hour), resetsAt, overage, notice, updatedAt. Optionally pct (the share of the current window used, 0 to 100), limitTok (the window's token cap when a session knows it), weekResetsAt and weekPct for the 7-day window. The window tiles use each one when it is posted and say so while it is missing; they never guess a cap.

A project is working now when a session runs or a running job reported in the last 30 minutes. It is active when it is working, has an open job, or had any report in the last 72 hours; an active project that is not working reads Idle. A project marked paused or done is inactive; a pinned project stays active. Token figures count every token the model reads or writes, cached context included; most are cache reads, which cost about a tenth of new input. Cost is at API list prices, as Claude Code reports it, rounded to whole dollars. The figure at the end of the open jobs adds each open job's tokEst less its tokens so far; a job with a time estimate and no tokEst runs at the project's current rate; a job with neither is not counted and the line says so. Its cost uses the project's own dollars per token. Cloud sessions come from an hourly sync and, where the page may use the Claude Code Remote connector, from a live read every 10 minutes. Cowork and local CLI sessions appear only when they report, and a report marked partial is a floor. A rate counts only tokens that two readings at most 3 hours apart place in time, spread evenly between them. Tokens used before the first reading, or between readings further apart, count in the totals and in no hour. Windows end at the newest reading and say how much of them the readings cover. Times are in your clock.
